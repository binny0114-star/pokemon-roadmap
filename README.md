# 포케루트 (Poké Route)

1–5세대 본가 21개 버전과 8세대 소드·실드·브릴리언트 다이아몬드·샤이닝 펄을 합한 25개 버전에서 좋아하는 포켓몬 1–6마리 또는 단일 타입 챌린지를 고르면, 파티와 그 파티 전용 스토리 로드맵을 결정론적으로 만드는 오프라인 우선 한국어 웹 앱입니다. 게임 레지스트리는 Pokémon LEGENDS Z-A까지 1–9세대 39개 버전, 전국도감은 #001–1025를 다룹니다. 기술 데이터 범위는 고정된 원본에 실제 행이 있는 버전 그룹만 지원합니다.

`카탈로그` 게임은 파티 로드맵을 생성하지 않습니다. X/Y부터 스칼렛/바이올렛까지 14개 클래식 본편과 레츠고 2개 버전, LEGENDS 아르세우스는 별도 화면에서 검수된 장·보스 순서를 미리볼 수 있습니다. 카탈로그 전용 게임의 입수 데이터는 화면에 표시하지 않습니다. 이 가운데 완전 지원으로 승격된 소드·실드·BDSP를 제외한 게임은 스토리·입수·버전별 기술표 세 기능이 모두 완비되지 않았으므로 추천 엔진에 연결하지 않습니다. 레츠고와 LEGENDS 계열은 각각 독립 메커니즘으로 분류하며, 레츠고 비전기술과 PLA 라이드를 표시하고 체육관/HM 구조를 억지로 재사용하지 않습니다.

Gen 6–7 8개 버전은 레지스트리의 7개 정확성 게이트(입수, 폼, 기술, 진화, 스토리, 이동 메커니즘, 통합)를 모두 통과해야만 `완전 지원`으로 바뀝니다. 2026-09-12 검수에서 **승격된 게임은 0/8개**입니다. Gen 6은 PKHeX 야생·고정·선물·알·화석·게임 내 교환과 폼/슬롯, Gen 7은 별도 버전별 야생·SOS 자원을 보존합니다. PokéAPI 그룹 15–18은 기본 폼 추천용 표와 별도로 알 기술을 포함한 자력기·TM/HM·가르침 원본 행을 784/811/944/959개 폼별 포켓몬 식별자로 보존합니다. 다만 PKHeX Gen 6 `Standard`에는 풀숲·동굴·파도타기·낚시·DexNav 구분이 없고 Gen 7 legality 행에는 일반 테이블/SOS 맥락과 테이블 식별자가 없습니다. PokéAPI는 ORAS 파도타기·낚시·DexNav·무리배틀과 Gen 7 조우가 불완전하며 PKHeX 슬롯에 손실 없이 결합할 폼/슬롯 키도 없습니다. 조우율 누락만으로 차단하지는 않지만, 플래너에 필요한 정확한 방식과 최초 도달 시점을 증명할 수 없어 카탈로그 전용을 유지합니다. 선택한 미리보기 화면에서 각 게이트의 한국어 근거와 차단 사유를 확인할 수 있습니다.

레츠고·소드/실드·BDSP·LEGENDS 아르세우스 7개 버전도 같은 7개 게이트와 별도 `gen8-completeness` 매니페스트를 사용합니다. 2026-09-12 검수에서 **소드·실드·브릴리언트 다이아몬드·샤이닝 펄 4/7개가 승격**되어 파티·로드맵을 완전 지원합니다. 고정 PokéAPI 그룹 19/20/23/24의 폼별 기술 행은 각각 188/750/491/247개 포켓몬 식별자로 격리해 보존합니다. 소드·실드는 PKHeX 고정 리비전의 숨은·심볼·레이드·갑옷섬·왕관설원 입수를 날씨·배지·DLC 조건과 함께 정규화하고, TM 획득 장, TR 와트 비용·일일 순환과 DLC 장 연대기를 반영합니다. BDSP는 지하대동굴·조건부 풀의 해금 조건, 1회용 TM 보장 수량과 포켓치 비전기술을 반영합니다. 레츠고는 포획 콤보 출현 보정과 TM·파트너 기술가르침 획득 장이, LEGENDS 아르세우스는 대량발생·시공의 뒤틀림·임무·조사단 랭크와 기술 상점·숙달 해금 시점이 고정 원본에 없어 카탈로그 전용을 유지합니다. 소스 행 수만으로 승격하지 않고 이 필드들을 매니페스트의 차단 항목으로 기계 검증합니다.

카탈로그에는 출시된 본가의 스토리 진행형 기본 게임·페어·서드/강화판·후속작·리메이크를 포함합니다. DLC는 소속 게임의 데이터 그룹으로 기록하되 별도 게임처럼 세지 않습니다. 메가디멘션은 LEGENDS Z-A의 데이터 그룹이고, Pokémon Champions처럼 배틀 전용인 작품과 Pokémon Pokopia처럼 본가 스토리 로드맵 대상이 아닌 작품은 제외합니다.

은·크리스탈·사파이어·에메랄드는 기존 검수 파티를 한 번에 필수 멤버로 불러오는 단축 버튼도 제공합니다.

## 실행과 검증

```bash
npm install
npm run dev
npm run lint
npm test
npm run validate:data
npm run generate:data:check
npm run build
```

정적 원본 스냅샷을 다시 생성할 때만 인터넷이 필요합니다.

```bash
npm run generate:data
```

정적 도감·입수·기술 데이터는 런타임 외부 API 없이 동작합니다. Supabase 환경 변수를 설정한 배포에서만 선택적인 온라인 로그인·동기화가 사용됩니다.

## 생성기 동작

1. 버전을 선택합니다.
2. 밸런스 파티 또는 해당 세대의 단일 타입 챌린지를 선택합니다.
3. 검색 가능한 전국도감에서 필수 멤버 1–6마리를 선택합니다. 단일 타입 모드의 첫 선택은 데이터 수정으로 교체할 Lv.5 스타팅입니다.
4. 무교환, 필드기 편의, 전설, 엔딩 후 입수 허용을 설정합니다.
5. 엔진이 스토리 합류 시점, 남은 보스 상성, 공격 타입 다양성, 공통 약점, 종족값 역할, 버전별 필드기 기여를 점수화합니다.
6. 점수 동률은 전국도감 번호로 결정하므로 같은 입력은 항상 같은 파티를 만듭니다.

필수 멤버는 자동으로 제거되지 않습니다. 추천 멤버는 잠그거나 상위 대안으로 교체할 수 있으며, 잠금 외 슬롯만 다른 결정론 대안으로 재생성할 수 있습니다. 스타터·화석 상호 배타, 6마리 초과, 통신진화, 엔딩 후 입수, 세대 미등장, 이벤트/타 버전 교환 전용은 생성 전에 명시적으로 차단합니다.

단일 타입 챌린지는 복합 타입을 포함해 모든 전투 멤버가 선택 타입을 공유하도록 후보·대안·임시 보스 대응을 제한합니다. 첫 번째 필수 포켓몬은 사용자가 게임 데이터를 수정해 원래 스타터 대신 받는 Lv.5 포켓몬으로 취급합니다. 따라서 해당 세대에 존재하고 선택 타입을 공유한다면 원래 버전의 조우·교환진화·엔딩 후 제한을 받지 않습니다. 나머지 멤버는 실제 버전별 입수 조건을 그대로 지킵니다. 원래 스타터 이벤트는 교체되므로 다른 원래 스타터는 추가 추천하지 않습니다.

희소 타입에 개조 스타팅과 실제 획득 가능한 서로 다른 진화 계열을 합쳐 6개 미만이면 가능한 1–5마리만 구성하고 부족 수를 경고합니다. 진행 필드기를 맡을 타입 밖 임시 요원이 필요하면 이동용으로만 사용하고 전투에는 참가시키지 않는 규칙을 안내합니다.

## 동적 로드맵

완전 지원되는 10개 스토리 패밀리(`RGBY`, `GSC`, `RSE`, `FRLG`, `DPPt`, `HGSS`, `BW`, `B2W2`, `SWSH`, `BDSP`)만 추천 엔진에 연결됩니다. 1–5세대 8개 패밀리는 공통 연대기와 보스 데이터를 공유하고 버전 차이를 덮어쓰며, `SWSH`·`BDSP`는 검수된 현대 스토리 모델의 장·보스를 그대로 사용합니다. 카탈로그 전용인 5개 현대 스토리 패밀리(`XY`, `ORAS`, `SM`, `USUM`, `SV`)는 미리보기 모델로만 사용합니다. 생성된 파티마다 다음 항목을 다시 합성합니다.

- 포획 위치·레벨·합류 장과 데이터 품질
- 단계별 진화 시점과 통신교환 경고
- 버전별 실제 자력기·TM/HM·기술가르침 호환과 당시의 기술 타입·위력
- 진화형의 Lv.1 전용 기술은 세대별 기술 떠올리기 NPC 위치·비용·해금 장 이후에만 안내
- 진화 전 형태의 자력기는 정상 진화 레벨 전에 습득 가능한 경우에만 최종 형태의 유지 기술로 사용
- 해당 장까지 합류·진화·습득 가능한 멤버만 사용한 보스 대응
- 늦게 합류하는 필수 멤버의 임시 카운터
- 단일 타입 규칙과 해당 타입 안에서 가능한 임시 카운터
- 1–4세대 1회용 TM 충돌 가능성
- 해당 세대/버전에 존재하는 HM·필드기만 사용한 배치표

진행률 키는 `버전 + 생성 플랜 ID`로 분리되어 파티 변경이 다른 진행 기록을 덮어쓰지 않습니다. 데이터 수정으로 액션이 다른 장으로 이동해도 기존 완료 체크는 액션 정체성을 기준으로 새 위치에 자동 승계됩니다.

## 로컬 트레이너 계정

헤더의 로그인 메뉴에서 닉네임과 숫자 PIN으로 이 브라우저 전용 계정을 만들 수 있습니다. PIN은 PBKDF2-SHA-256으로 해시해 저장하며, 빌더 상태·현재 플랜·체크리스트 진행률·클리어 목록은 계정별로 분리됩니다. 로드맵의 모든 파티 액션을 체크하면 사용 버전, 챌린지 유형, 파티와 완료 날짜가 클리어 목록에 기록됩니다.

Supabase 환경 변수가 없으면 계정 데이터는 오프라인 우선 원칙에 따라 외부 서버로 전송되지 않습니다. 이 로컬 PIN 모드에서는 같은 브라우저에서만 복원되며, 첫 계정 생성 시 기존 게스트 플랜과 진행률을 자동으로 가져옵니다.

Supabase를 구성하면 이메일 매직 링크 기반 **온라인 동기화**가 추가됩니다. 온라인 로그인 사용자는 빌더 상태, 현재 플랜, 체크리스트 진행률과 클리어 목록을 본인 계정의 단일 상태 문서로 저장하므로 브라우저 저장 데이터를 삭제하거나 다른 기기로 이동해도 다시 로그인하여 복원할 수 있습니다.

### Supabase 구성

1. Supabase 프로젝트를 만들고 `supabase/migrations/20260830013311_planner_cloud_state.sql`을 적용합니다.
2. `supabase/config.toml`의 Auth 설정을 `supabase config push`로 적용합니다. 무료 플랜에서는 기본 매직 링크 이메일을 사용합니다.
3. Auth URL Configuration의 Site URL이 `https://binny0114-star.github.io/pokemon-roadmap/`인지 확인합니다.
4. 로컬 개발은 `.env.example`을 `.env.local`로 복사해 프로젝트 URL과 **publishable key**를 입력합니다.
5. GitHub Actions에는 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` 저장소 시크릿을 등록합니다.

`planner_state` 테이블은 RLS가 활성화되어 있으며, 인증된 사용자는 `auth.uid()`와 일치하는 자기 행만 조회·삽입·수정할 수 있습니다. `service_role` 또는 secret key를 브라우저 번들에 넣지 마세요.

## 데이터 구조

- `src/data/version-registry.json`: 1–9세대 39개 버전, 페어·서드·강화판·후속작·리메이크 구분, PokéAPI 버전/그룹 ID, 메커니즘 패밀리, 플래너 지원 수준과 Gen 6–7 정확성 게이트 근거

정적 종·진화·조우·기술 스냅샷은 레지스트리에 고정된 원본에서 생성합니다. 기존 1–5세대 추천과 플랜 ID는 호환 스냅샷을 덮어써 그대로 보존합니다. 현대 입수 스냅샷은 GPL-3.0인 PKHeX 자원에서 생성하며, PokéAPI 버전 ID나 PKHeX 내부 enum 대신 안정적인 레지스트리 게임 ID로 저장합니다. 각 생성 파일은 리비전, 입력 파일, 전국도감/세대 경계, 버전·버전 그룹별 행 수와 명시적 데이터 공백을 기계 판독 가능한 `provenance`·`coverage`로 기록합니다. `npm run generate:data:check`는 같은 리비전에서 결과가 재현되지 않으면 실패합니다. 스토리·보스·이동 해금과 버전 차이는 공개 워크스루를 버전별로 검수했으며, 스칼렛/바이올렛은 실제 선행 조건 DAG와 권장 오픈월드 순서를 분리합니다.

조우 스냅샷은 장소만이 아니라 세부 구역, 풀숲·낚싯대·파도타기·바위깨기·박치기·선물·고정 심볼 같은 방식, 출현 확률과 시간대·계절·대량발생·포켓트레·라디오·스토리 조건을 보존합니다. 입수 시점은 장소 진입 장과 해당 도구/필드기/조건 해금 장 중 늦은 쪽으로 계산합니다. 더블슬롯이나 이벤트 배포가 필요한 경로는 일반 입수로 취급하지 않으며, 엔딩 후 구역과 전국도감 조건은 엔딩 전 추천에서 제외합니다. 특수 심볼의 세부 이벤트 순서를 정적 원본만으로 완전히 확정할 수 없는 경우에는 `시점 추론`으로 표시합니다.

기술 스냅샷은 버전 그룹을 합치지 않고 실제 자력기 레벨, TM/HM 번호, 기술가르침 호환과 기술 변경 이력을 포함합니다. 생성기와 런타임은 종·기술의 등장 세대가 대상 게임보다 늦으면 해당 행을 거부합니다. 따라서 구세대 미등장 기술이나 해당 포켓몬이 배울 수 없는 기술은 추천하지 않으며, 1–3세대 타입 기반 물리/특수 분류와 당시의 기술 타입·위력을 적용합니다. 자력기는 정확한 레벨에 배치하지만 일반 TM과 기술가르침의 지도상 획득 위치는 아직 별도 스냅샷이 없어 보수적인 스토리 장에 `시점 추론`으로 표시합니다. 위치 토큰을 한국어로 확정하지 못한 경우 영문 원본 위치를 숨기지 않고 그대로 노출합니다. 그린은 기존 저장 데이터와 플랜 ID를 보존하기 위해 Blue 조우 스냅샷 별칭을 유지하며 레지스트리에 이를 명시합니다.

PokéAPI 그룹 15–18의 X/Y·ORAS·SM·USUM 자력기·알·TM/HM·기술가르침 원본 행은 `pokemon.identifier`별 완전 합법성 계층에 필터 없이 보존합니다. 현재 추천 엔진은 호환성을 위해 별도의 기본 폼·유효 기술 표를 계속 사용하며, 폼별 타입/종족값과 지도상 TM·가르침·떠올리기 해금 장은 아직 연결하지 않습니다. 갑옷의 외딴섬·왕관의 설원·벽록의 가면·남청의 원반·LEGENDS Z-A·메가디멘션처럼 독립 행이 없는 그룹은 0행으로 유지하며 다른 그룹에 임의 합치지 않습니다. 특히 그룹 30·31은 버전 레지스트리와 세대 경계 검증을 위한 메타데이터일 뿐 기술표 지원을 뜻하지 않습니다. PKHeX Gen 6 `Standard`와 Gen 7 일반 슬롯은 폼·장소·슬롯·레벨을 그대로 두고 `wild-unspecified`로 명시해 세부 방식을 발명하지 않습니다. 외부 감사에서도 ROM 없이 재배포 가능한 손실 없는 대체 데이터는 확인되지 않았습니다. pk3DS는 사용자가 추출한 ROM이 필요하고, 공개 디컴파일은 없으며, 확인한 다른 덤프는 명확한 재배포 라이선스가 없어 사용하지 않습니다. 따라서 정확한 진행 방식·도달 게이트가 없는 풀과 누락된 고정·선물 입수는 추천 데이터로 승격하지 않습니다. 멜메탈처럼 원본 진화 행이 없는 종은 `missing-source`로, 원본 버전 그룹이 종의 등장 세대보다 이른 알려진 비정상 행은 보정 내역으로 기록합니다.

전국도감 행은 안정적인 종 ID와 기본 폼만 제공합니다. 생성기는 `pokemon.is_default = 1`인 포켓몬만 종 조우·기술표에 연결하고, 지역 폼·메가진화·전투 폼의 `pokemon_id`를 기본 종에 합치지 않습니다. 해당 비기본 폼의 타입·진화·조우·기술 계획은 `default-form-only / unsupported`로 명시되며 후속 폼 레지스트리 없이는 추천에 사용하지 않습니다.
